# 담소 React Native 프론트엔드

Expo SDK 56 / React Native 0.85.3 / Expo Router / TypeScript. 웹은 React Native Web으로 같은 화면을 렌더링합니다.

## 실행

저장소 루트에서 `powershell -ExecutionPolicy Bypass -File scripts/start-damso-preview.ps1`을 실행하고 http://localhost:8081 을 엽니다. 기존 서재 서버(5174)와 Expo 웹 서버(8081)를 함께 실행합니다. 이 스크립트는 이미 실행 중인 포트의 프로세스를 종료하지 않습니다.

수동 실행:

1. `damso-library`에서 `npm run web:dev`
2. `damso-mobile`에서 `npm run web`

처음 설치할 때는 각 폴더에서 `npm ci`를 실행합니다. 모바일 개발은 `damso-mobile`에서 `npm start` 또는 `npm run android`로 시작합니다. 기기에 맞는 Expo Go 또는 개발 빌드가 필요합니다.

## 이번 범위

- 큰 질문과 마이크 중심의 부모·자녀 홈.
- 날짜별 2D 서재, 역할 필터, 이야기 상세.
- ‘3D 화면으로 보기’ → 실제 모델 로딩 → 기존 Room.glb/Three.js 서재. 재시도·2D 복귀 포함.
- 톱니바퀴 설정 탭: 글자 크기·부모/자녀 역할 전환·가족 호칭 선택.
- 텍스트 답변은 원문 그대로 현재 메모리에 추가합니다. 앱 새로고침 시 초기화됩니다. 예시 기록은 ‘예시’로 구분합니다.

계정·가족 연결·백엔드·실제 녹음·STT·LLM·TTS·이야기 영구 저장은 이번 프론트 구현에 연결하지 않았습니다. 3D 책/액자에는 기존 프로토타입의 예시 데이터가 남아 있으며, 2D에서 작성한 기록과 동기화하지 않습니다.

## 3D 연결

기존 `../damso-library`의 모델과 장면을 그대로 사용합니다. 웹에서는 iframe, Android/iOS에서는 React Native WebView로 장면을 표시합니다. 3D 자체는 Three.js 웹 렌더러이며 네이티브 GL로 다시 구현한 것이 아닙니다. 모델을 두 번 복사하거나 새 방으로 대체하지 않았습니다.

로딩 완료는 모델 준비 후 두 프레임이 지난 시점의 `damso-room-ready` 메시지로 판단합니다. 웹은 메시지 출처의 origin과 iframe window를 함께 검증합니다. 60초 동안 준비 신호가 없거나 모델 렌더링에 실패하면 재시도 화면을 제공합니다.

실물 기기에서 127.0.0.1은 개발 PC가 아닙니다. `.env.example`을 참고해 `EXPO_PUBLIC_LIBRARY_3D_URL`에 기기에서 접근 가능한 HTTPS 서재 주소를 설정하세요. Android 에뮬레이터 기본값은 10.0.2.2:5174입니다. 네이티브 기기 빌드·터치 성능은 별도 검증 대상입니다.

## 검증

`npm test`, `npm run typecheck`, `npm run lint`, `npm run export:web`.

2026-10-18 기준 위 명령과 `npx expo install --check`를 통과했습니다. 브라우저의 375×844 화면에서 글자 크기·역할 전환, 텍스트 작성, 역할 필터, 이야기 상세, 실제 3D 모델 로딩 및 2D 복귀를 확인했습니다. Android/iOS 빌드는 실행하지 않았습니다.

현재 열린 8081 테스트 사이트는 `npm run export:web` 결과를 기존 Vite의 `preview --outDir dist --host 127.0.0.1 --port 8081 --strictPort`로 제공하며, 5174에서는 기존 3D 앱이 실행됩니다. 개발용 실행 스크립트를 다시 사용하면 Expo 개발 서버로 실행됩니다.

의존성 점검에서 Expo SDK 56의 전이 의존성 보안 경고 29건(높음 19, 보통 10)이 남아 있습니다. 일반 `npm audit fix`를 적용했으며 SDK를 강제 다운그레이드하는 수정은 적용하지 않았습니다. 현재는 로컬 프론트 검토용이고, 외부 배포 전 SDK 보안 패치 및 영향 범위를 다시 확인해야 합니다.

기존 꽃길·페이퍼로지 폰트의 WOFF 압축 컨테이너를 TTF로 변환하여 같은 글리프를 앱에 포함했습니다. 기존 서체 출처와 라이선스는 `../damso-library/public/fonts/README.md` 및 `assets/fonts/Paperlogy-LICENSE.txt`를 참고하세요.

## 가족 호칭 설정 (2026-10-19)

설정에서 자녀로 보기를 선택한 뒤 가족 설정에서 `어머니·아버지·엄마·아빠·부모님`을 고릅니다. 선택은 AsyncStorage에 저장되어 다시 열어도 유지됩니다. 이 미리보기에는 예시 가족 한 쌍만 있으므로 로컬 호칭도 그 가족 기준이며 실제 계정과 동기화하지 않습니다. 저장 실패는 화면에 표시합니다.

서재 목록·필터·상세는 조회자에 따라 `어머니의 이야기`, `나의 이야기`, `민수의 이야기`를 표시합니다. 자녀 홈의 함께하는 가족 호칭도 반영합니다. 기록 본문은 이름이나 가족 관계를 치환하지 않습니다. 역할과 글자 크기, 새로 쓴 예시 기록은 기존처럼 실행 중 메모리에만 보관합니다.

백엔드의 연결별 호칭 저장·조회 API도 구현되어 있지만 현재 프론트 미리보기와의 로그인/API 통합은 별도입니다. Expo SDK 56의 [공식 AsyncStorage 안내](https://docs.expo.dev/versions/v56.0.0/sdk/async-storage/)와 [React Native 0.85 접근성 안내](https://reactnative.dev/docs/0.85/accessibility)를 기준으로 구현했습니다.

호칭 기능 검증: 웹 375×844·844×375 및 앱 내 큰 글씨에서 표시·선택을 확인했습니다. 별도 새 탭 실행에서도 호칭 유지, 목록·필터·상세 반영을 확인했고, 모바일 단위 검사 3개·타입 검사·린트·웹 내보내기를 통과했습니다. 실제 Android/iOS 실행과 계정 API 통합은 검증 범위에 포함하지 않았습니다.

## 온보딩과 자동 말투 정리

`http://localhost:8081/onboarding`은 호칭 설정과 ‘녹음된 평소 말투와 비슷하게 요약해요’ 안내를 제공합니다. 문체를 반드시 선택하던 두 번째 단계는 제거했습니다. 기본 `auto`는 원문 종결어미를 살린 1인칭 요약이며 반복·말버릇만 정리하고 불분명한 말투는 해요체를 사용합니다. 설정에서 원하는 사용자만 담백한 일기으로 고정할 수 있습니다.

선택은 AsyncStorage에 저장됩니다. 이전 필수 문체 선택은 auto로 전환하되 호칭·역할·온보딩 완료 여부는 보존합니다. 프론트는 계정/API 연결 전의 기기 내 미리보기이므로 서버 프로필과 자동 동기화하지 않습니다. 기존 이야기와 원문은 다시 쓰지 않습니다. 백엔드는 별도로 `summary_style` 저장·LLM 전달을 지원합니다.


## 서버 연결 및 재답변·추가 질문

설정의 로그인에서 가족 연결을 마친 계정을 연결하면 실제 서버 질문과 서재를 사용합니다. 미연결 상태는 기존 미리보기입니다. 토큰은 실행 중 메모리에만 유지합니다. `EXPO_PUBLIC_API_URL` 기본값은 `http://127.0.0.1:8000`이며 실기기에서는 서버 접근 주소로 바꿉니다.

Expo 56의 expo-audio로 녹음해 업로드하고 STT→LLM 상태를 확인합니다. 관련 이야기 없음은 재녹음/글/건너뛰기로 안내하고 원본은 서버의 비공개 이력으로 유지합니다. 요약 확인 후 공개합니다. 추가 질문은 하루 1개이며 가족이 서재에서 요청한 이야기는 다음 날 우선 표시합니다. 기본 질문은 유지합니다. 클라이언트 단독 제한이 아니라 서버/DB에서 제한합니다.

2026-10-20: 타입 검사, lint, 기존 6개 테스트, 웹 export 통과. 브라우저에서 실제 HCX 정리와 가족 예약 확인. 휴대폰 녹음과 Android/iOS 빌드는 미검증입니다. 회원가입·연결 코드 화면의 서버 연동과 푸시 알림은 별도 작업입니다.


## 2026-10-21 이야기 사진과 손글씨

기본·개별·AI·가족 예약을 합해 하루 최대 3개를 서버가 제한합니다. 기본 1개, AI 최대 1개, 다음 날 가족 예약 최대 1개이며 매일 3개를 채우는 방식은 아닙니다. 이 설명이 위의 이전 추가 질문 한도 설명보다 우선합니다.

공개된 본인 이야기의 `관련 사진 등록하기`에서 시스템 사진 선택기를 엽니다. 이야기 안에서 사진을 확대하고, 2D 서재의 `가족 앨범 보기`와 3D 액자에서 같은 가족 앨범으로 이동합니다. 인증된 미디어만 읽으며 토큰을 이미지 URL에 넣지 않습니다. 3D 책은 이야기 목록으로 이동합니다. 3D 앱을 단독 실행하면 앨범 연동 안내만 표시하며 실제 가족 사진은 로그인한 모바일 앱에서 조회합니다.

이야기 본문만 손글씨 3개를 사용하며 `다른 글씨체로 보기`로 순환합니다. 페이지를 새로 열면 첫 번째 기본 글씨로 돌아옵니다. UI에 실제 폰트 이름은 표시하지 않습니다. 원본 파일·라이선스는 assets/fonts/StoryHandwriting-SOURCES.md 및 StoryHandwriting-LICENSE.txt에 기록했습니다.

검증: 모바일 단위 테스트 8개, TypeScript·lint·Expo 웹 export, 3D Vite build 통과. 브라우저의 390×844에서 글씨 전환·사진 등록·확대·앨범을 확인했습니다. Android/iOS 사진 선택과 실제 기기의 메모리·로딩 성능은 미검증입니다.


### 원문·원음과 작은 글씨 버튼

이야기 화면의 `원문과 원음`을 펼치면 원문 텍스트(글 입력 또는 STT 전사문)와 원음 플레이어를 확인합니다. 재생·일시정지·재생 시간 표시와 끝난 음원 다시 듣기를 지원합니다. 녹음이 없거나 가족에게 공유하지 않은 항목은 해당 안내를 표시합니다. 기존의 큰 글씨체 버튼은 질문 오른쪽의 작은 T로 변경했으며 누르는 영역은 48×48 이상을 유지합니다. 접근성 이름은 `다른 글씨체로 보기`입니다.

작성자 화면에서 원문 텍스트와 원음 공유를 각각 켜고 끕니다. 기본 원문 비공개와 기존 원음 공유 선택을 유지하고 가족은 허용된 항목만 읽습니다. 웹 원음은 인증 fetch 후 임시 Blob으로 재생하며 화면 종료·계정 변경 시 플레이어를 정리합니다. 화면을 떠나거나 앱이 비활성화되면 재생을 유지하지 않습니다. 원문은 손글씨 요약과 구별해 기본 앱 글씨로 표시합니다.

검증: 단위 테스트 9개, 타입·린트·웹 export 통과. 390×844 웹에서 T 전환, 원문 펼치기, 재생·일시정지, 가족 공유 표시를 확인했습니다. 재생용 음원은 테스트음이며 실제 음성 품질 평가는 별도입니다. Android/iOS 청취는 미검증입니다.
