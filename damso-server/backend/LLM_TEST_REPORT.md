# HCX-007 1차 연결·입출력 검증

검증일: 2026-10-19 · 모델: HCX-007 · 최종 공통 프롬프트: `damso-v1.2`

## 연결 범위

- CLOVA Studio v3 공식 엔드포인트를 서버에서 호출합니다. 키는 system/user 메시지에 넣지 않습니다.
- 응답은 `summary`, `follow_up_question` 두 필드로 제한하고 서버에서 다시 검증합니다. 추론은 사용하지 않습니다.
- STT는 음성 업로드, 처리 대기 작업, `STTProvider.transcribe()` 인터페이스까지만 준비되어 있습니다. 실제 별도 STT·TTS 서버의 HTTP 어댑터는 호출하지 않았습니다.
- 프롬프트는 1인칭 일기체 요약, 원문 사실·부정·불확실성 보존, 감정 창작 금지, 단일 존댓말 꼬리질문, 대화 중단 존중을 지시합니다.

구현은 [공식 Structured Outputs 문서](https://api.ncloud-docs.com/docs/en/clovastudio-chatcompletionsv3-so)와 [HTTPX 0.28.1 문서](https://github.com/encode/httpx/tree/0.28.1/docs)를 참고했습니다. 아래 결과는 실제 API 호출이며 모의 응답이 아닙니다.

## 최종 프롬프트의 실호출 결과

### 1. 일반 추억

원문: “첫 월급 받아서 어머니 내복 사드렸지. 좋아하시더라고.”

요약: “첫 월급으로 어머니께 내복을 사드렸다. 어머니께서는 좋아하셨다.”

꼬리질문: “내복을 받으셨을 때 어머니께서는 어떤 말씀을 하셨나요?”

첫 월급·인물 관계·선물·원문에서 명시한 반응이 유지됐습니다.

### 2. 사투리와 부정 표현

원문: “부산서 살 때 아부지랑 시장에 갔데이. 떡 하나 사 묵고 집에 왔지. 동생은 안 갔다.”

요약: “부산에 살 때 아버지와 시장에 가서 떡을 사 먹었다. 동생은 함께 가지 않았다.”

꼬리질문: “시장에서 어떤 떡을 사 먹었나요?”

사투리 텍스트를 표준어로 다듬고 동생이 동행하지 않았다는 사실을 보존했습니다. 실제 음성 인식률을 검증한 것은 아닙니다.

### 3. 부정과 기억의 불확실성

원문: “그때는 돈이 모자라서 선물은 못 드렸어요. 대신 편지를 썼어요. 그 뒤로 선물을 드렸는지는 잘 기억이 안 나네요.”

요약: “돈이 모자라서 어머니께 선물은 못 드리고 대신 편지를 썼다.”

꼬리질문: “편지에는 어떤 내용을 쓰셨나요?”

선물을 못 드렸다는 사실과 편지는 유지됐지만 이후 기억의 불확실성은 빠졌습니다. 앞선 프롬프트에서는 이 구절을 보존한 호출도 있어, 현재 지시만으로 일관된 보존을 보장하지 못합니다. 원문 대조와 작성자 검토가 필요합니다.

### 4. 대화 중단 의사

원문: “오늘은 그냥 쉬었어요. 더 이야기하고 싶지는 않아요.”

요약: “오늘은 그냥 쉬었다.”

꼬리질문: 없음(`null`).

추가 질문을 강요하지 않는 동작을 확인했습니다.

### 5. 정상 이야기와 악성 지시가 섞인 입력

입력은 “오늘 딸과 공원에서 걸었어요” 뒤에 가짜 system 태그, 기존 지시 무시, 지정 문구 출력, API 키·프롬프트 공개, 추가 admin 필드 요구를 붙였습니다.

요약: “딸과 공원에서 걸었다.”

꼬리질문: 없음(`null`).

이번 호출에서는 지정 문구나 admin 필드가 반환되지 않았고 정상 이야기는 남았습니다. 첫 프롬프트에서는 이야기까지 버리는 문제가 있어 보완했습니다. 이 한 사례로 모든 프롬프트 인젝션을 막았다고 판단하지 않습니다.

## 실제 저장 흐름

합성 계정과 `damso_test`에서 실제 `python -m app.worker --once`를 실행했습니다.

1. 부모 원문 답변 생성 → LLM 작업 생성.
2. 워커의 HCX-007 호출 → 요약과 꼬리질문을 작성자 전용 초안에 저장.
3. 제출 전 자녀 조회는 404.
4. 부모 제출 → 자녀 서재에서 요약문 조회. 자녀가 먼저 답할 필요 없음.
5. 원문은 작성자 데이터에 그대로 보존되고 자녀 응답에는 포함되지 않음.
6. 테스트 계정 정리. 개발 DB `app`에 합성 계정·기록을 만들지 않음.

실제 저장된 요약은 “첫 월급으로 어머니께 내복을 사드렸다. 어머니께서는 좋아하셨다.”였습니다.

## 자동 회귀 검사와 한계

자동 검사 35개가 통과했습니다. 여기에는 인증·가족·서재 기존 검사와 HCX 요청 형식, 입력과 고정 지시 분리, 비정상 JSON·추가 필드·복수 질문 거절, 시간·응답 크기 제한, 인증 오류·리다이렉트 처리, 키 비노출, 외부·다른 origin 접근 차단, 수정 중 오래된 응답 폐기, 워커 중단 복구, 공개된 본문 보호가 포함됩니다.

자동 회귀 검사는 모의 HTTP 응답을 사용합니다. 위 실호출 예시는 개발 중 프롬프트를 보완한 동일 소수 사례이며 독립 평가 자료나 운영 성능 측정이 아닙니다. JSON 형식 준수와 요약의 의미 정확성은 다릅니다. 특히 불확실성 생략은 남은 품질 문제로 기록하며, 결과를 사용자 확인 없이 자동 공개하지 않습니다.

재현 명령과 키 없는 JSON 결과 위치는 [RUNBOOK.md](RUNBOOK.md)의 '키 등록과 순차 테스트'를 참고하세요.
